## 1. 项目画像（需求与目的）

### 1.1 是什么
为公共卫生领域基层管理者（疾控监督员等）提供的**纯个人**工作台。统一管理任务、台账、会议、培训、灵感，消除碎片化工具切换与信息遗漏。

### 1.2 给谁用
- 主用户：疾控监督员 / 公卫基层管理者（办公室负责人视角）。
- 使用环境：办公电脑（Windows）为主，偶尔手机浏览器查看。
- **用户多重身份**：可能是项目负责人、带教老师、科室负责人等，不要把它窄化为"给疾控监督员用的纯个人工具"。

### 1.3 核心目的（北极星）
让基层管理者专注于"做正确的事"，而不是"记住要做的事"。

### 1.4 明确不做什么（Non-goals，极易踩坑）
| 不做 | 原因 |
|------|------|
| 多人协作 / 团队共享 | 个人工作台定位 |
| 审批流程 | 无外部用户，审批在线下完成 |
| 即时通讯 / 消息通知 | 非沟通工具 |
| 与 OA 系统对接 | 复杂度远超收益 |
| 权限管理 / 登录账号 | 纯本地单人使用 |

> 注：「团队管理」模块是**个人视角管理团队**（成员是记录对象、不登录、不协作、数据不跨人同步），与上述定位**不冲突**，不要误判为需要解决的"矛盾"。

### 1.5 信息架构核心理念
以「工作记录（todos 表）」为统一数据底座。待办、重点、周期、台账（合同/采购/报销/会议/培训）、灵感均为其上的视图或关联实体。长期目标（is_goal 项）已**从待办页独立为单独导航页**（见第 4 节）。

## 2. 技术架构与本地运行

### 2.1 技术栈
- **纯前端单页应用**：单个 `index.html`，内联 JS/CSS，无框架、无构建步骤。
- **存储**：`localStorage` 直读直写（封装在 `DB.raw / DB.get / DB.set`）。
- **测试**：`tests/*.test.js` 为纯 Node 脚本（不依赖浏览器），用 `vm` 沙箱加载真实 `index.html` 函数做端到端断言。
- **运行环境**：Node 与 Python 均可用。Node 跑测试；本地预览用 Python 静态服务器。

### 2.2 本地预览
在 `index.html` 所在目录（项目根 `F:\workbuddy\workstation\workbench\`）执行：
```bash
D:\Anaconda3\python.exe -m http.server 8080
```
浏览器访问 `http://127.0.0.1:8080/index.html`（托管 Python 3.13.12 的 `http.server` 缺失 `_ctypes`，不可用，必须用 Anaconda 的）。

### 2.3 跑测试
在项目根目录执行（以下四条应全部 PASS）：
```bash
node tests/v14.test.js              # 既有单元测试 76/76

```
> 若系统 `node` 不在 PATH，可用 WorkBuddy 托管 Node：`C:\Users\User\.workbuddy\binaries\node\versions\22.22.2\node.exe`。

### 2.4 语法自检（改动后建议执行）
`index.html` 内联脚本可用 `new Function` 包裹提取的脚本段做语法校验（参考既有测试台做法）。

## 4. 需求与开发历程（做了什么 + 为什么）

### 4.1 起点：v1.4 重构目标
在 v1.3 基础上重构，统一数据模型、周期引擎、优先级体系，把"长期目标"从待办中剥离，修复若干交互缺陷。

### 4.2 用户 8 项反馈（已全部落地）
1. **周期选项不灵活** → 周期模型扩展为完整集（见 4.4）。
2. **待办"整理"确认没反应 + 缺优先级录入** → 根因为类型不安全的 `id` 匹配（`String(r.id)===String(id)` 缺失）导致静默 return；修复后整理弹窗含四象限优先级选择。
3. **长期目标不好看、不显眼、无法区分** → 目标卡改为左色条 + 进度环（后续又统一为 `.todo-card` 体系）。
4. **周期再生需要关停机制** → "已完成(DONE)"触发生成下一期，"已关闭(CLOSED)"即关停（见 4.5）。
5. **优先级不统一** → 统一为四象限：重要且紧急 / 重要不紧急 / 紧急不重要 / 不重要不紧急（常量 `PRIORITY`，旧值经 `PRIORITY_MIGRATE` 就近映射）。
6. **取消自动升重要** → 移除"无截止日自动升为重要"的逻辑。
7. **速记箱死代码清理** → 经只读扫描 273 个函数全部被引用，无孤立死函数；唯一冗余为 legacy 双周期模型（兼容保留，见 4.6）。
8. **全代码审计** → 见 7。

### 4.3 长期目标独立（用户："干脆把长期目标独立出来，待办里就是要做的事情"）
- 新增独立导航页「长期目标」（`renderGoals` / `goalCardHtml`）。
- `renderTodos` 移除目标置顶分组，只渲染 `!r.is_goal` 事项；目标的子任务（`parent_goal` 指向目标、`is_goal=false`）仍留在待办。
- 待办角标/计数排除目标；新建目标弹窗跳转目标页；仪表盘目标块加"管理 →"入口。

### 4.4 周期模型完整集
- 间隔类（保留）：`Nd` / `Nw` / `Nm` / `Nq` / `Ny` / `wd`（每工作日）。
- 固定日期类（新增）：`dom:N`（每月第 N 日）、`dow:X`（每周星期 X，1=一…7=日）、`doq:N`（每季第 N 日）、`yd:M-D`（每年 M 月 D 日）。
- 推算 `nextDueDate` + 辅助 `clampInt / nextMonthDay / nextWeekday / nextQuarterDay / nextYearDate`；显示 `formatLedgerRecurrence`。
- 状态弹窗 `updateRecurrenceUI()` 动态渲染对应输入（N 仅间隔类可见）。

### 4.5 周期生成 / 关闭修复（用户："周期任务生成和关闭还有问题"）
用 `vm` 沙箱端到端验证，坐实并修复 3 个缺陷：
- **S2 无截止日不生成**：`maybeRegenerate` 原 `if(!rec.due_date) return` 静默失败 → 改为 `base = rec.due_date || todayStr()`。
- **S3/S6 关停链不彻底 / 周期复活**：关闭只跳过本实例再生，未阻止同组后续实例繁衍；重开已关闭项再完成会复活。
  → 新增 `stopRecurrenceGroup`：关闭周期项时置 `recurrence_stopped`，并把同组"未开始/进行中"后续实例 `recurrence` 改为 `'none'`（整条链停）；`maybeRegenerate` 加 `if(rec.recurrence_stopped) return` 守卫。
- 待办卡上已停周期项显示灰标"周期已停"。

### 4.6 待办关联长期目标全流程（用户："关联全流程有问题"）
端到端测试（路径：新建关联 / 整理关联 / 智能录入关联 / 渲染分离 / 防御）17/17，定位并修复：
- **流程断点（核心）**：智能录入（最高频新建入口）`saveSmart` 创建待办时不传 `parentGoal`，弹窗无"关联目标"下拉 → 新建无法一步关联。已在 `smartModal` 加下拉并贯通 `saveSmart`。
- **边界 bug**：目标可在整理弹窗自我关联（下拉含自身），导致 `goalProgress` 把目标自身算进子任务、进度环错乱。已在 `createLedgerItem` 与 `applyOrganize` 两处加自我关联拦截。

### 4.7 长期目标页风格统一（用户："保持和其他页面一样的设计"）
`goalCardHtml` 重构为复用 `.todo-card` / `.todo-card-header` / `.todo-card-title` / `.todo-card-meta` 体系，进度环改用主题色变量；删除旧内联自定义样式。

## 7. 已知边界与遗留（勿动）

1. **Legacy 双周期模型并存**：`todos` 表同时承载 v1.4 字符串式 `recurrence`（ledger 周期再生，见 `maybeRegenerate`/`stopRecurrenceGroup`）与 1.3 遗留对象式 `recurrence`（`type:'recurring'` + `calcNextDue` / `formatRecurrence` / `completeRecurringTodo`）。两套并存、互不冲突。**删除 legacy 会改变旧 recurring 待办行为，禁止清理。**
2. **id 类型混用**：legacy 数据 `id` 可能为字符串，所有查找必须 `String(r.id)===String(id)`，禁止改回严格 `===`。
3. **优先级字段**：入库统一用 `normPriority` 归一化；显示用 `priorityTag`。旧值 high/mid/low/important/normal 经 `PRIORITY_MIGRATE` 映射。
4. **`ensureV14` 迁移**：只加字段，保留回退；改动迁移逻辑需格外谨慎。
