# 我的工作台 — 团队管理模块设计方案

> 版本：V1.0 | 日期：2026-07-20 | 关联需求：《团队管理_需求文档.md》V1.1
> 说明：本文档为主 agent 终审核后产出的实现蓝图，供后续落地"个人视角团队管理"模块使用。需求文档为权威输入。

## 一、概述

### 1.1 来源与定位
本设计方案基于《团队管理_需求文档.md》V1.1。需求文档经"产品视角 + 技术视角"双 agent 头脑风暴协作收敛，并由独立评审 agent 对照 10 条验收清单挑刺、打回重写一轮后 **PASS** 产出。本方案在其基础上做最终实现路线设计。

### 1.2 不变的核心决策（实现时严禁偏离）
1. **纯个人视角**：成员是记录对象、不是使用者；不登录、不协作、不共享、数据不跨人同步。
2. **`todos` 零改动**：团队任务仅 `category:['团队']` 打标，绝不新增 `owner` 等字段。
3. **`TeamAssignment.status` 统一规则**：非 `standalone` 来源一律不落库，查询时由被引用实体（todo/actionItem/training）实时派生；仅 `standalone` 自带并持久化。DB 不写、不回写、不同步。
4. **字段命名规范**：`content`/`note`/`name`/`title` 沿用；时间字段统一 `YYYY-MM-DD`；软删除 `deleted:true`。
5. **外部机构走 `agencys`**：本模块只管内部人。

## 二、模块架构（前端）

### 2.1 技术底座（沿用，不引入新依赖）
- 原生 JS + ES Modules（`type="module"`）；抽象 `DataStore`（`DB` 对象，含 `get/set/nextId/raw` + 软删除过滤）；简单 `EventEmitter` 做模块间通信。
- 数据存 `localStorage`，Gitee 同步仅作个人跨设备备份。
- 保持"无构建工具、无框架"的现有约束（PRODUCT_DESIGN.md 九）。

### 2.2 代码组织（目标 vs 现状）
- **目标结构**（若后续做代码拆分）：新增 `js/modules/team.js` 承载花名册/委派/忙闲/汇总；`js/utils.js` 增加 `resolveMember()`；成员选择器作为全局组件。
- **现状适配**（当前 `index.html` 为单体约 5700 行内联）：在 `index.html` 内新增渲染函数 `renderTeam()`、委派同步函数、成员选择器弹窗，并在 `navigate()` 中注册 `'team'` 路由；数据集合直接挂在 `DB` 对象下。两种写法功能等价，优先按现状落地，拆分可后置。

### 2.3 新增/扩展清单
| 类型 | 名称 | 说明 |
|------|------|------|
| 新增集合 | `teamMembers` / `teamAssignments` / `teamMetrics` | 与 `todos`/`meetings`/`trainings` 同级 |
| 新增渲染 | `renderTeam()` | 花名册 + 委派追踪 + 忙闲看板 + 团队汇总的统一页 |
| 新增工具 | `resolveMember(name)` | `TeamMember.name` 模糊匹配，返回成员或建议新建 |
| 新增组件 | 成员选择器 | 输入联想选人；用于会议行动项、独立委派、培训关联 |
| 扩展 | 待办页"成员视图"tab | 选成员后只读 join `TeamAssignment` 过滤其任务（`todos` 不改） |
| 扩展 | 会议/培训 | 接入成员选择器 + "生成委派"按钮 |
| 扩展 | 驾驶舱 | 新增"团队维度"统计区块 + 下钻成员明细 |

## 四、数据模型规格（实现契约）

> 完整 TypeScript 接口见需求文档 4.2–4.5。此处复述**实现必须死守的契约**。

### 4.1 TeamMember（花名册主数据）
- `id`/`name`(join key)/`role?`/`group?`/`contact?`/`note?`/`tags?`/`deleted?`
- 标准集字段；`contact` 最小化收集（仅工作联系方式，非必填）。

### 4.2 TeamAssignment（委派枢纽）
- `id`/`memberId`/`sourceType`(`meetingAction`|`training`|`todo`|`standalone`)/`sourceRef`/`status?`/`deadline?`/`note?`/`createdAt`(`YYYY-MM-DD`)/`deleted?`
- **status 契约（最关键）**：
  - `sourceType` ∈ {`todo`,`meetingAction`,`training`} → `status` **不入库**，查询时派生：
    - `todo` → 读 `todos.status`
    - `meetingAction` → 读 `actionItems[].done`（完成态）+ `actionItems[].deadline`（逾期判定）
    - `training` → 读 `trainings.status`
  - `sourceType` = `standalone` → `status` 自带并持久化；`deadline` 自带
- **sourceRef 解析**：`todo`→`todos.id`；`meetingAction`→`meetings.id`（按 `member.name` 匹配 `assignee`，可选 `assigneeMemberId` 精确定位）；`training`→`trainings.id`（**手动关联建立**，用户逐人建派）；`standalone`→`0`

### 4.3 TeamMetric（考核卡，P2）
- `id`/`memberId`/`period`/`dimensions?`/`events?`/`note?`/`createdAt?`(`YYYY-MM-DD`)

### 4.4 既有实体零改动
- `todos`：不新增字段；团队任务仅 `category:['团队']`
- `meetings.actionItems[].assignee`：保持字符串，可选补 `assigneeMemberId`
- `trainings.organizer`：保持字符串

## 五、UI/UX 思路

1. **花名册页**：列表 + 搜索 + 按 `group`/`tags` 筛选；新建/编辑弹窗（标准集字段）；软删除默认隐藏、可在"已离队"视图追溯。
2. **委派面板**：从待办 / 会议 / 培训 / 独立 四种来源建派；选人统一走成员选择器。
3. **成员视图 tab**：选成员 → 展示其进行中 / 逾期 / 已完成任务（join `TeamAssignment`，只读过滤，`todos` 一字不改）。
4. **忙闲看板**：卡片/列表，基于"进行中/待办委派数"派生忙/闲；可手动覆盖；逾期项高亮。
5. **团队汇总**：按成员聚合完成率、逾期率、负载；驾驶舱团队维度可下钻成员明细。
6. **成员选择器**：输入即联想；无匹配时提示"加入花名册"（是否允许弹窗一键新建待定，见开放问题）。

## 六、与现有模块集成点（具体 hook）

| 集成点 | 实现方式 |
|--------|----------|
| 委派同步 | 复用 `syncLedgerTodo()` 范式（`index.html` 现有）：会议/培训落库时 upsert 对应 `TeamAssignment` |
| 成员字典化 | `resolveMember(name)` 在 `meetings.actionItems.assignee` / `trainings.organizer` 输入处调用，匹配花名册 |
| 成员视图 | 待办渲染层 join `TeamAssignment.memberId→todoId` 过滤，纯只读映射 |
| 提醒 | 复用现有 deadline 提醒机制；`standalone` 读自带 `deadline`，`todo` 来源读 `todos.deadline` |
| 统计 | 复用现有完成率/逾期算法（同一套函数），成员维度在查询层 union 两套来源 |
| 导出 | 复用现有 CSV 导出范式（`index.html` 现有），扩展成员维度；导出时可隐去 `contact` |

## 八、关键实现契约（防止 B1 类问题回潮）

1. **status 派生规则写进代码注释与 `repairData` 校验**：非 `standalone` 的 `TeamAssignment` 记录中不允许持久化 `status` 值；任何派生展示都在查询层计算。
2. **`todos` 零侵入**：建立委派不得修改 `todos` 任何字段；加自动化断言（建立前后 `todos` diff 为空）。
3. **时间字段统一 `YYYY-MM-DD`**：新增实体的 `createdAt` 一律该格式，`repairData()` 归一化。
4. **软删除一致**：`teamMembers`/`teamAssignments`/`teamMetrics` 删除统一 `deleted:true`，不物理删。
